# Verify External Facts

Verify the exact model/version/limit at issue using current official documentation or a public
catalog. These read-only lookups are within ordinary research scope; they do not require another
approval. Do not substitute training memory or expand into a provider-wide survey.

Distinguish public documentation from runtime probes. Authenticated provider calls, paid inference,
private runtime access, and Discord delivery require matching user authorization under `AGENTS.md`.
For an authorized probe, prefer the existing bounded project diagnostic; use short timeouts and
bounded results. Never expose keys, Cookies, authorization headers, or private payloads.

When a source is unavailable, use tracked configuration, lockfiles, fixtures, or cached catalogs
as dated evidence and state what remains unverified. Report the source and relevant observation
time; distinguish network/authentication/rate-limit failure from a confirmed absent model or code
error. Do not install a dependency or create a script merely to verify a transient fact.
